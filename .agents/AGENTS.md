# Agent Rules

## Git Commit and Push Behavior
- **Automatic Commits**: You may perform automatic git commits for changes you make. All commit messages must be written in English only (never in Italian or any other language).
- **NO Pushes**: DO NOT perform `git push` operations under any circumstances. Git push is strictly reserved for the user to execute from the terminal.
- **Nessun Push (Italiano)**: NON eseguire `git push` in nessun caso. Il push è riservato esclusivamente all'utente da eseguire tramite terminale. Tutti i messaggi dei commit devono essere scritti esclusivamente in inglese.

## Development Rules
- **No `!important`**: The use of `!important` in CSS is strictly forbidden.
- **No Duplicate CSS**: Do not write duplicate CSS rules; keep stylesheets clean and organized.
- **No Inline JavaScript**: Avoid inline JavaScript in HTML/components; keep behavior separated.
- **Descriptive Names**: Always use descriptive and meaningful names for variables, functions, classes, and other identifiers.
- **Minimal Commenting**: Comment code only when necessary (e.g., to explain non-obvious logic or structural decisions), avoiding obvious or redundant comments.
- **Avoid Workarounds**: Do not use hacky workarounds; write robust and clean solutions.
- **Structural Issues**: If you encounter a structural problem in the codebase, propose a proper solution or refactoring instead of piling up more code or patching it.

## Regole di Sviluppo (Italiano)
- **Vietato `!important`**: È vietato l'uso di `!important` nei CSS.
- **Niente CSS duplicato**: Evita il CSS duplicato; mantieni i fogli di stile puliti e organizzati.
- **Niente JavaScript inline**: Evita JavaScript inline; separa la logica di comportamento.
- **Nomi descrittivi**: Usa sempre nomi descrittivi e significativi per variabili, funzioni, classi e identificatori.
- **Commenti essenziali**: Commenta il codice solo quando serve veramente (es. per spiegare logiche non ovvie o decisioni strutturali), evitando commenti superflui o ovvi.
- **Evita workaround**: Non usare workaround temporanei o "pezze"; scrivi soluzioni robuste e pulite.
- **Problemi strutturali**: Se riscontri un problema strutturale, proponi una soluzione o un refactoring adeguato invece di aggiungere altro codice sopra.
