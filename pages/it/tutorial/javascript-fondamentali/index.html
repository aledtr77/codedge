Il primo clic

Premi il pulsante. Guarda cosa cambia.

Qui JavaScript fa una cosa precisa: aspetta un clic e cambia una frase nella pagina. Prima del clic leggerai “Nessun clic, per ora.”; dopo leggerai “Hai premuto il pulsante!”. Prova e guarda la risposta.

Il pulsante e la frase sono elementi HTML. Il codice JavaScript collega l’azione sul pulsante alla modifica della frase. Nei passaggi successivi userai questa stessa idea per contare i clic, scegliere una risposta e leggere un nome scritto nella pagina.

La pagina nel browserIn attesa

Nessun clic, per ora.

Per rifare la prova ti serviranno un browser e un editor di codice, per esempio Visual Studio Code: scrivi nei file, salvi e controlli il risultato nel browser. Se i pulsanti e gli attributi HTML ti sono ancora poco familiari, puoi partire dalla guida HTML.

Segui il progetto fino al pulsante “Azzera”. Poi usa le sezioni finali quando vuoi esplorare altre possibilità del linguaggio. Se il pulsante qui non è attivo, gli esempi e le istruzioni nei capitoli restano leggibili.

Porta il primo clic nei tuoi file

Crea una cartella prova-js e aprila nell’editor. Dentro crea index.html e script.js. In index.html scrivi:

<!doctype html>
<html lang="it">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>La mia prima prova JavaScript</title>
  <script src="script.js" defer></script>
</head>
<body>
  <h1>La mia prima prova</h1>
  <button id="pulsante" type="button">Mostra messaggio</button>
  <p id="risultato" aria-live="polite">Nessun clic, per ora.</p>
</body>
</html>

In script.js scrivi:

const pulsante = document.querySelector("#pulsante");
const risultato = document.querySelector("#risultato");

pulsante.addEventListener("click", () => {
  risultato.textContent = "Hai premuto il pulsante!";
});

Salva i file e apri index.html nel browser. Prima del clic leggi “Nessun clic, per ora.”; dopo il clic leggi “Hai premuto il pulsante!”. Cambia il testo tra virgolette in script.js, salva e ricarica: il messaggio nuovo apparirà al prossimo clic.

src="script.js" indica il file nella stessa cartella. defer fa eseguire questo script dopo che il browser ha letto l’HTML: il pulsante esiste già quando JavaScript lo cerca. Se non succede nulla, controlla il nome del file e apri la console del browser per cercare un errore.

Segui il percorso del clic

document.querySelector("#pulsante") trova l’elemento con id="pulsante". Il simbolo # segue la sintassi dei selettori CSS. La seconda riga trova il paragrafo. const dà un nome a ciascun elemento trovato, così puoi usarlo nelle righe successive.

addEventListener("click", ...) registra una funzione da eseguire quando arriva un clic. Le istruzioni tra { e } non partono subito. Al clic, textContent sostituisce il testo del paragrafo. Questo è il DOM: la struttura della pagina che JavaScript può leggere e modificare.

Prova a cambiare #risultato in #inesistente e ricarica. Il clic non funziona: il selettore non trova un elemento, quindi risultato vale null. Rimetti #risultato. Il nome nell’HTML e quello nello script devono coincidere.

Per un elemento con ID puoi usare anche document.getElementById("risultato"): qui usiamo querySelector perché permette anche selettori di classe e di elemento.

Fai ricordare i clic alla pagina

Ora il messaggio è sempre uguale. Vogliamo contare quante volte premi il pulsante. Sostituisci tutto il contenuto di script.js con questo:

const pulsante = document.querySelector("#pulsante");
const risultato = document.querySelector("#risultato");
let clic = 0;

pulsante.addEventListener("click", () => {
  clic = clic + 1;
  risultato.textContent = `Clic: ${clic}`;
});

Ricarica e premi tre volte: vedi “Clic: 1”, poi “Clic: 2”, poi “Clic: 3”. let crea una variabile che riassegni a ogni clic. const va bene per pulsante e risultato, perché non assegni loro un altro elemento. Il testo tra accenti gravi è una template string: ${clic} inserisce il valore corrente.

Ricaricando la pagina il conteggio riparte da zero: la variabile esiste solo finché la pagina resta aperta.

Al terzo clic, cambia risposta

Al terzo clic vogliamo un messaggio diverso. Lascia le prime tre righe come sono e sostituisci l’intero blocco pulsante.addEventListener(...):

pulsante.addEventListener("click", () => {
  clic = clic + 1;
  if (clic === 3) {
    risultato.textContent = "Hai raggiunto tre clic!";
  } else {
    risultato.textContent = `Clic: ${clic}`;
  }
});

Ricarica: ai primi due clic vedi il numero; al terzo compare il messaggio speciale; al quarto torna “Clic: 4”. if controlla una condizione. === confronta senza convertire automaticamente tipi diversi: il numero 3 è diverso dal testo "3". else gestisce gli altri casi.

Dai un nome alla decisione

La decisione sul testo può avere un nome. Sostituisci script.js con questa versione completa:

const pulsante = document.querySelector("#pulsante");
const risultato = document.querySelector("#risultato");
let clic = 0;

function messaggioPer(numeroClic) {
  if (numeroClic === 3) {
    return "Hai raggiunto tre clic!";
  }
  return `Clic: ${numeroClic}`;
}

pulsante.addEventListener("click", () => {
  clic = clic + 1;
  risultato.textContent = messaggioPer(clic);
});

Ricarica e ripeti i quattro clic: il risultato è lo stesso del capitolo precedente. messaggioPer riceve un numero come parametro e restituisce il testo con return. La funzione del clic usa quel testo per aggiornare la pagina. Separare la scelta del messaggio dall’azione sul browser rende più facile controllare le due cose.

Fai entrare il nome nel messaggio

Aggiungi un campo per il nome. In index.html, subito prima del pulsante, inserisci:

<label for="nome">Il tuo nome</label>
<input id="nome" type="text" autocomplete="name">

Ora sostituisci script.js con questa versione. La funzione per il messaggio resta la stessa; il clic legge il campo e aggiunge un saluto se contiene testo:

const pulsante = document.querySelector("#pulsante");
const risultato = document.querySelector("#risultato");
const campoNome = document.querySelector("#nome");
let clic = 0;

function messaggioPer(numeroClic) {
  if (numeroClic === 3) {
    return "Hai raggiunto tre clic!";
  }
  return `Clic: ${numeroClic}`;
}

pulsante.addEventListener("click", () => {
  clic = clic + 1;
  const nome = campoNome.value.trim();
  const saluto = nome ? `Ciao, ${nome}. ` : "";
  risultato.textContent = saluto + messaggioPer(clic);
});

Ricarica, scrivi “Ada” e premi: vedi “Ciao, Ada. Clic: 1”. Se lasci il campo vuoto, vedi solo il conteggio. value legge ciò che hai scritto; trim() toglie gli spazi all’inizio e alla fine. La forma condizione ? valore1 : valore2 sceglie tra due testi. textContent mostra il nome come testo, senza interpretarlo come HTML: prova a scrivere <b>Ada</b> per verificarlo.

Quando il clic non dà il risultato atteso

Apri gli strumenti di sviluppo del browser e la scheda Console. Se la pagina non reagisce, controlla in ordine: script.js è nella stessa cartella? Gli ID nell’HTML coincidono con quelli di querySelector? Hai salvato e ricaricato?

Puoi aggiungere temporaneamente console.log(clic); dopo clic = clic + 1;. Alla pressione del pulsante, in Console devono apparire 1, 2, 3. Il messaggio di log compare negli strumenti, non nella pagina. Togli la riga quando hai finito. Un errore rosso con numero di riga indica dove iniziare a cercare; un clic che non produce log suggerisce di controllare il collegamento del file o il listener.

Ora prova tu: aggiungi Azzera

Obiettivo: dopo alcuni clic, il pulsante “Azzera” deve riportare il conteggio a zero e mostrare “Clic: 0”. Il campo del nome può restare com’è. Prima aggiungi in index.html un secondo pulsante sotto quello esistente:

<button id="azzera" type="button">Azzera</button>

Nel file JS cerca quel pulsante, ascolta il suo clic, assegna 0 a clic e aggiorna risultato.textContent. Prova questa sequenza: due clic sul primo pulsante, reset, un altro clic. Il testo deve mostrare 1, 2, 0, 1. Così verifichi che lo stato si sia davvero azzerato.

Mostra una soluzione possibile

Questa è un’aggiunta in fondo al tuo script.js, non un nuovo file:

const pulsanteAzzera = document.querySelector("#azzera");

pulsanteAzzera.addEventListener("click", () => {
  clic = 0;
  risultato.textContent = "Clic: 0";
});

Il reset modifica la stessa variabile usata dal primo pulsante. Se modifichi solo il testo visibile, al clic successivo il vecchio conteggio ricompare.

Cinque domande per orientarti nel codice

Dove si trova l’elemento?
document.querySelector("#id"); con un ID puoi usare anche document.getElementById("id").
Quando parte il codice?
addEventListener("click", funzione) reagisce a un evento del browser.
Quale dato cambia?
let per un valore da riassegnare; const quando non riassegni il nome.
Come scegli il risultato?
if e === controllano una condizione; return restituisce il risultato di una funzione.
Come aggiorni la pagina?
textContent scrive testo nell’elemento; value legge un campo.

Controlla cosa hai capito

Dieci domande sugli esempi della guida. Ogni risposta include una spiegazione.

Scrivere una nota nel file

Un commento serve a spiegare una scelta nel file; il browser non lo esegue. Puoi scriverlo su una riga con // oppure su più righe tra /* e */. Per esempio, sopra le due selezioni puoi ricordare perché devono corrispondere all’HTML:

// Gli ID devono coincidere con quelli in index.html.
const pulsante = document.querySelector("#pulsante");
const risultato = document.querySelector("#risultato");

Aggiungi il commento e ricarica: la pagina si comporta esattamente come prima. Non serve commentare ogni istruzione; qui stai segnando una dipendenza tra due file.

Quando i dati sono più di uno

Se vuoi raccogliere più traguardi, un array mantiene una lista in ordine; un oggetto associa nomi a valori. Sono due modi diversi di organizzare dati. Puoi provare queste righe nella Console e leggere il risultato dei due console.log:

const traguardi = [3, 5, 10];
const impostazioni = { nome: "Ada", limite: 10 };
console.log(traguardi[0]); // 3: il primo elemento ha indice 0
console.log(impostazioni.nome); // Ada: una proprietà per nome

Questo esempio è separato dal contatore: non devi copiarlo in script.js per completare la prova.

Conservare un valore dopo la ricarica

La variabile clic riparte da zero a ogni ricarica. localStorage può conservare una stringa nel browser. Per un numero occorre convertirla quando la rileggi:

localStorage.setItem("clic", String(clic));
const valoreSalvato = localStorage.getItem("clic");
const clicSalvati = valoreSalvato === null ? 0 : Number(valoreSalvato);

Queste righe mostrano le operazioni, non sono un nuovo script.js completo. Il dato resta nel browser finché non lo cancelli. Non usare questo spazio per password o informazioni sensibili.

Aspettare una risposta dal server

Un clic è un evento che arriva più tardi. Anche una richiesta di rete termina più tardi: async e await permettono a una funzione di aspettare il risultato senza bloccare tutta la pagina. Questo esempio richiede un server che risponda a /api/messaggio; non funzionerà aprendo il file HTML da solo.

async function caricaMessaggio() {
  try {
    const risposta = await fetch("/api/messaggio");
    if (!risposta.ok) throw new Error("Risposta non valida");
    const dati = await risposta.json();
    risultato.textContent = dati.messaggio;
  } catch (errore) {
    risultato.textContent = "Impossibile caricare il messaggio.";
    console.error(errore);
  }
}

try/catch gestisce gli errori, per esempio una connessione interrotta. L’esempio mostra il punto in cui si aspetta e quello in cui si mostra il risultato; non sostituisce il progetto del contatore.

Decidere quando parte lo script

Nel progetto abbiamo usato defer: il file viene scaricato mentre il browser legge l’HTML e viene eseguito dopo che l’HTML è stato analizzato. Uno script classico senza attributi eseguito nell’head può fermare la lettura dell’HTML. async esegue lo script non appena è pronto, quindi non garantisce che gli elementi della pagina esistano già né l’ordine rispetto ad altri script. I moduli type="module" sono differiti per impostazione predefinita.

Quando una funzione aspetta una richiesta di rete, il browser può continuare a gestire altre attività; poi riprende la funzione quando il risultato è disponibile. Questo coordinamento coinvolge l’event loop. Per la prima prova basta sapere che il codice dentro il listener parte al clic, non quando la pagina viene caricata.
