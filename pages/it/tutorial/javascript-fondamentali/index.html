Il primo clic

Premi il pulsante. Guarda cosa cambia.

Qui JavaScript fa una cosa precisa: aspetta un clic e cambia una frase nella pagina. Prima del clic leggerai “Nessun clic, per ora.”; dopo leggerai “Hai premuto il pulsante!”. Prova e guarda la risposta.

Il pulsante e la frase sono elementi HTML. Il codice JavaScript collega l’azione sul pulsante alla modifica della frase. Nei passaggi successivi userai questa stessa idea per contare i clic, scegliere una risposta e leggere un nome scritto nella pagina.

La pagina nel browserIn attesa

Nessun clic, per ora.

Per rifare la prova ti serviranno un browser e un editor di codice, per esempio Visual Studio Code: scrivi nei file, salvi e controlli il risultato nel browser. Se i pulsanti e gli attributi HTML ti sono ancora poco familiari, puoi partire dalla guida HTML.

Segui il progetto fino al pulsante “Azzera”. Poi usa le sezioni finali quando vuoi esplorare altre possibilità del linguaggio. Se il pulsante qui non è attivo, gli esempi e le istruzioni nei capitoli restano leggibili.

Porta il primo clic nei tuoi file

Crea una cartella prova-js e aprila nell’editor. Dentro crea index.html e script.js. In index.html scrivi:

<!doctype html>
<html lang="it">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>La mia prima prova JavaScript</title>
  <script src="script.js" defer></script>
</head>
<body>
  <h1>La mia prima prova</h1>
  <button id="pulsante" type="button">Mostra messaggio</button>
  <p id="risultato" aria-live="polite">Nessun clic, per ora.</p>
</body>
</html>

In script.js scrivi:

const pulsante = document.querySelector("#pulsante");
const risultato = document.querySelector("#risultato");

pulsante.addEventListener("click", () => {
  risultato.textContent = "Hai premuto il pulsante!";
});

Salva i file e apri index.html nel browser. Prima del clic leggi “Nessun clic, per ora.”; dopo il clic leggi “Hai premuto il pulsante!”. Cambia il testo tra virgolette in script.js, salva e ricarica: il messaggio nuovo apparirà al prossimo clic.

src="script.js" indica il file nella stessa cartella. defer fa eseguire questo script dopo che il browser ha letto l’HTML: il pulsante esiste già quando JavaScript lo cerca. Se non succede nulla, controlla il nome del file e apri la console del browser per cercare un errore.

Leggi il codice del primo clic

Il file script.js contiene istruzioni: JavaScript le legge dall’alto verso il basso quando la pagina si apre. Le prime due righe cercano il pulsante e il paragrafo nell’HTML. document rappresenta la pagina; querySelector cerca un elemento; #pulsante significa “l’elemento con id="pulsante"”. Le virgolette indicano un testo da usare come selettore, non un nome di variabile.

const pulsante = document.querySelector("#pulsante");
const risultato = document.querySelector("#risultato");

const dà un nome al valore trovato. Dopo queste righe puoi usare pulsante e risultato senza cercare di nuovo gli elementi. Se scrivi un ID diverso da quello nell’HTML, querySelector restituisce null, cioè “nessun elemento”. Prova a cambiare temporaneamente #risultato in #manca: al clic la Console segnala un errore. Rimetti l’ID giusto.

La riga con addEventListener dice al browser: “quando arriva un clic, esegui le istruzioni tra le parentesi graffe”. La funzione tra () => { ... } è il codice da eseguire più tardi. textContent cambia il testo del paragrafo. Questa struttura modificabile della pagina si chiama DOM. All’apertura dello script non compare ancora il messaggio nuovo: serve il clic.

Le parentesi tonde () passano dati a una funzione; le graffe {} racchiudono istruzioni; = assegna un valore; il punto permette di usare una proprietà o una funzione di un elemento. Qui usiamo il punto e virgola per segnare la fine di un’istruzione. Puoi rileggere il codice del capitolo precedente seguendo questo percorso: cerca gli elementi, aspetta il clic, cambia il testo.

Leggi e aggiorna la pagina: il DOM

La pagina non è soltanto il testo scritto nell’HTML. Quando il browser lo legge costruisce una struttura di elementi che JavaScript può cercare e modificare: il DOM. document dà accesso alla pagina; querySelector restituisce il primo elemento che corrisponde a un selettore CSS.

const titolo = document.querySelector("h1");
const risultato = document.querySelector("#risultato");
console.log(titolo.textContent);
risultato.textContent = "Messaggio aggiornato";

textContent legge o sostituisce il testo. Se il selettore non trova nulla, il risultato è null: controlla che l’elemento esista prima di usarne le proprietà. Per aggiungere elementi usa createElement e append. Per mostrare testo digitato preferisci textContent; innerHTML interpreta contenuto come markup e può eseguire HTML non desiderato se gli passi dati non fidati. In questa guida non serve per mostrare una frase.

La pagina ha più strumenti del solo testo

Il DOM è l’albero di elementi che il browser costruisce dall’HTML. querySelector restituisce il primo elemento che corrisponde a un selettore CSS; querySelectorAll restituisce tutti quelli corrispondenti, in una raccolta che puoi scorrere. Se non esiste una corrispondenza, il primo restituisce null.

const righe = document.querySelectorAll(".voce");
righe.forEach((riga) => {
  riga.classList.add("letta");
});
const scheda = document.querySelector("[data-stato]");
scheda.dataset.stato = "completata";

classList.add aggiunge una classe senza cancellare le altre; remove la toglie e toggle la alterna. Gli attributi HTML descrivono l’elemento; dataset offre accesso agli attributi data-*. Per creare un elemento usa document.createElement, imposta il suo textContent e inseriscilo con append. Evita di costruire markup con testo digitato dall’utente.

Prima di contare: quali valori usa JavaScript?

Un valore è un dato con cui il programma lavora. "Hai premuto il pulsante!" è testo, detto stringa; 0 e 3 sono numeri; true e false sono valori booleani, usati per rispondere a domande sì/no. === pone una domanda: “questi due valori sono uguali e dello stesso tipo?”. Apri la scheda Console negli strumenti del browser, incolla una riga alla volta e premi Invio. console.log mostra un valore negli strumenti, senza cambiare la pagina.

console.log("Clic: " + 1);  // Clic: 1
console.log(1 + 1);         // 2
console.log(1 === 1);       // true

La prima riga unisce testo e numero: il risultato è testo. La seconda somma due numeri. La terza chiede se i numeri sono uguali e restituisce un booleano. Le righe dopo // sono note per chi legge; JavaScript non le esegue. typeof 1 mostra "number", mentre typeof "1" mostra "string": la cifra può sembrare uguale, ma il tipo cambia il risultato delle operazioni.

Esistono anche valori che indicano un’assenza. undefined significa spesso che un valore non è stato assegnato; null è l’assenza restituita da querySelector quando non trova un elemento. Non devi memorizzare tutti i tipi ora: distingui prima numero, testo, booleano e assenza, perché li incontrerai subito nel contatore.

Operatori: calcolare, confrontare, collegare

Un operatore svolge un’operazione su valori. + somma numeri o concatena stringhe; % restituisce il resto; === confronta valore e tipo; >= confronta grandezze. I confronti restituiscono un booleano: true o false.

const totale = 4 + 3;
const resto = 7 % 3;
const traguardoRaggiunto = totale >= 7;
const continua = traguardoRaggiunto && true;
console.log(totale, resto, continua); // 7, 1, true

&& richiede che entrambe le condizioni siano vere; || ne richiede almeno una; ! inverte un booleano. += aggiorna una variabile aggiungendo un valore: clic += 1 equivale a clic = clic + 1. Le parentesi chiariscono i gruppi, per esempio (nomeValido && traguardoRaggiunto) || accessoSpeciale. Usale quando una regola combina più operatori, così l’ordine resta leggibile.

Stringhe e template literal

Una stringa è testo racchiuso tra apici singoli, doppi o backtick. Per inserire valori in un messaggio, i template literal usano i backtick e ${...}:

const nome = "Ada";
const clic = 3;
const messaggio = `Ciao ${nome}, hai fatto ${clic} clic.`;
console.log(messaggio); // Ciao Ada, hai fatto 3 clic.

Dentro ${...} puoi mettere una variabile o un’espressione come ${clic + 1}. Gli apici non interpolano: "Ciao ${nome}" contiene letteralmente quei caratteri. I backtick permettono anche stringhe su più righe. Prova a cambiare nome e clic; il messaggio viene composto usando i valori nuovi.

Confrontare valori e tipi senza sorprese

=== confronta valore e tipo; == può convertire i tipi prima del confronto. Per questo 3 == "3" è vero, mentre 3 === "3" è falso. Nella maggior parte dei confronti di un programma, usa === e converti esplicitamente il dato quando vuoi confrontare numeri.

const valoreDalCampo = "3";
const numero = Number(valoreDalCampo);
console.log(valoreDalCampo === 3); // false
console.log(numero === 3);         // true
console.log(Number.isNaN(Number("ciao"))); // true

NaN segnala un calcolo numerico non valido; per riconoscerlo usa Number.isNaN, non un confronto con ===. Anche typeof null restituisce "object" per una particolarità storica del linguaggio: per sapere se un valore è proprio null, usa valore === null. Questi controlli espliciti evitano conversioni invisibili e risultati inattesi.

Valori truthy e falsy

if può controllare direttamente un valore: JavaScript lo considera truthy o falsy. Sono falsy false, 0, "", null e undefined; una stringa con uno spazio è invece truthy. Per questo è meglio verificare un campo con nome.trim() !== "", non soltanto con if (nome).

const nome = "Ada";
const saluto = nome ? `Ciao ${nome}` : "Scrivi il tuo nome";
console.log(saluto);

L’operatore ternario è condizione ? valoreSeVera : valoreSeFalsa, utile per una scelta breve. valore ?? alternativa usa l’alternativa solo per null e undefined; valore || alternativa la usa per qualunque valore falsy, compresi zero e stringa vuota. Se zero è valido, ?? evita di sostituirlo per errore.

Una variabile fa ricordare i clic

Il primo script reagisce, ma non ricorda quanti clic sono arrivati. Una variabile è un nome associato a un valore. Scriveremo let clic = 0 prima del listener: parte da zero e potrà ricevere un numero nuovo. Sostituisci tutto script.js con questa versione completa:

const pulsante = document.querySelector("#pulsante");
const risultato = document.querySelector("#risultato");
let clic = 0;

pulsante.addEventListener("click", () => {
  clic = clic + 1;
  risultato.textContent = "Clic: " + clic;
});

Salva, ricarica e premi tre volte: il paragrafo mostra “Clic: 1”, “Clic: 2”, “Clic: 3”. A ogni clic, la parte destra di clic = clic + 1 calcola il numero successivo; = lo assegna a clic. let permette questa nuova assegnazione. const è adatto a pulsante e risultato, perché in questo script quei nomi continuano a indicare gli stessi elementi.

clic è fuori dalla funzione del listener: rimane disponibile tra una pressione e la successiva. Se lo dichiarassi dentro, ripartirebbe da zero a ogni clic. Ricaricando la pagina il valore torna a zero, perché per ora esiste solo nella memoria della pagina aperta.

Una domanda produce una scelta

Vogliamo un messaggio speciale al terzo clic. La domanda “il numero di clic è 3?” produce true o false. === confronta due valori senza trasformare automaticamente un testo in numero. if esegue un blocco quando la risposta è vera; else copre gli altri casi.

Lascia le prime tre righe di script.js. Sostituisci solo il blocco che inizia con pulsante.addEventListener con questo:

pulsante.addEventListener("click", () => {
  clic = clic + 1;
  if (clic === 3) {
    risultato.textContent = "Hai raggiunto tre clic!";
  } else {
    risultato.textContent = "Clic: " + clic;
  }
});

Ricarica: al primo e al secondo clic vedi il numero; al terzo il messaggio speciale; al quarto “Clic: 4”. Cambia 3 in 2, salva e ricarica: il messaggio speciale si sposta al secondo clic. Hai modificato una regola, non l’HTML. clic === "3" sarebbe falso perché "3" è testo, mentre clic è un numero.

Più casi: else if e switch

Con else if JavaScript controlla più condizioni in ordine e usa il primo blocco vero. L’ultimo else copre i casi restanti. È una forma chiara per soglie o regole combinate:

if (clic === 0) {
  risultato.textContent = "Inizia con un clic";
} else if (clic < 3) {
  risultato.textContent = `Clic: ${clic}`;
} else {
  risultato.textContent = "Traguardo raggiunto";
}

switch confronta invece la stessa espressione con valori precisi. Ogni case indica un valore; break impedisce di proseguire nel caso seguente. default gestisce il resto. Per intervalli numerici è più leggibile if; per un valore preciso con molti esiti può essere più leggibile switch.

switch (clic) {
  case 0: risultato.textContent = "Nessun clic"; break;
  case 3: risultato.textContent = "Tre clic"; break;
  default: risultato.textContent = `Clic: ${clic}`;
}

Dai un nome a un lavoro ripetibile

La scelta del messaggio può vivere in una funzione: un gruppo di istruzioni a cui dai un nome e che puoi chiamare quando serve. Tra le parentesi tonde scrivi il parametro, il nome del dato che la funzione riceve. return restituisce il risultato al punto in cui la funzione è stata chiamata e conclude quella chiamata. Qui il risultato sarà un testo. Sostituisci script.js con questa versione completa:

const pulsante = document.querySelector("#pulsante");
const risultato = document.querySelector("#risultato");
let clic = 0;

function messaggioPer(numeroClic) {
  if (numeroClic === 3) {
    return "Hai raggiunto tre clic!";
  }
  return "Clic: " + numeroClic;
}

pulsante.addEventListener("click", () => {
  clic = clic + 1;
  risultato.textContent = messaggioPer(clic);
});

Ricarica e premi quattro volte: il risultato è quello del capitolo precedente. Quando scrivi messaggioPer(clic), passi il valore corrente di clic alla funzione. Dentro la funzione quel valore si chiama numeroClic: è un parametro. return consegna il testo al punto della chiamata; dopo return la funzione termina.

Prova nella Console messaggioPer(2) e messaggioPer(3): ottieni testi diversi senza cambiare il contatore visibile. La funzione prepara il testo; il listener decide quando usarlo e lo scrive nel DOM. Questa distinzione ti aiuta a capire quale parte del codice calcola e quale parte aggiorna la pagina.

Forme delle funzioni e parametri predefiniti

Hai già visto function e una funzione freccia usata come callback. Se il corpo di una funzione freccia è una sola espressione, questa viene restituita implicitamente; con più istruzioni servono graffe e return.

function raddoppia(numero) {
  return numero * 2;
}
const triplica = (numero) => numero * 3;
const saluta = (nome, formula = "Ciao") => `${formula}, ${nome}`;
console.log(raddoppia(4), triplica(4), saluta("Ada"));

I nomi nella definizione sono parametri; i valori passati alla chiamata sono argomenti. In saluta("Ada"), il parametro formula usa il valore predefinito. La funzione freccia e la funzione dichiarata non sono sempre intercambiabili: una freccia non crea un proprio this. Qui scegli in base a cosa rende più chiara la funzione. triplica è la funzione; triplica(4) la esegue.

Dove esiste una variabile?

Una variabile dichiarata dentro le graffe di una funzione è locale: il resto dello script non può leggerla direttamente. numeroClic esiste dentro messaggioPer; clic è dichiarata fuori, quindi la funzione del listener può leggerla. Prova questa piccola esperienza nella Console:

{
  const numero = 2;
  console.log(numero); // 2
}
// Qui "numero" non è più disponibile.

Le graffe creano un blocco. Con let e const, il nome esiste nel blocco in cui è stato dichiarato. Puoi usare const per un nome che non riassegni e let quando assegnerai un nuovo valore. Questo non significa che const renda immutabile ogni cosa: più avanti vedrai che il contenuto di un array può cambiare.

La funzione consegnata ad addEventListener si chiama callback: il browser la conserva e la chiama quando arriva il clic. La forma () => { ... } definisce una funzione senza darle un nome. La definizione avviene quando carichi la pagina; il codice al suo interno parte solo al clic.

var e l’ordine delle dichiarazioni

Oggi dichiara le variabili con const quando il nome non verrà riassegnato e con let quando cambierà. var è una dichiarazione più vecchia: ha visibilità di funzione invece che di blocco e permette di riutilizzare lo stesso nome nello stesso ambito, rendendo più facile creare errori.

if (true) {
  let dentro = "visibile qui";
  var fuori = "visibile nella funzione";
}
console.log(fuori);
// console.log(dentro); // ReferenceError

Le dichiarazioni var e le dichiarazioni di funzione vengono elaborate prima dell’esecuzione del loro ambito: questo comportamento è spesso chiamato hoisting. Non significa che sia una buona idea usarle prima di leggerle. let e const esistono nel blocco, ma non possono essere usate prima della riga di dichiarazione: quell’intervallo è la zona morta temporale e l’accesso produce un errore. Scrivi le dichiarazioni prima del loro uso: il flusso resta leggibile.

Una funzione può ricordare il suo contesto

Una closure si forma quando una funzione interna continua ad accedere alle variabili del blocco in cui è stata creata, anche dopo che quel blocco ha terminato. Non è una sintassi speciale: è il modo in cui JavaScript mantiene disponibile quel contesto.

function creaContatore() {
  let conteggio = 0;
  return function () {
    conteggio += 1;
    return conteggio;
  };
}
const prossimo = creaContatore();
console.log(prossimo()); // 1
console.log(prossimo()); // 2

creaContatore termina, ma la funzione restituita conserva accesso a conteggio. Ogni chiamata aggiorna quel valore privato. Anche il listener del clic può leggere clic perché la callback è stata creata nello stesso contesto. Le closure sono utili per mantenere uno stato senza renderlo globale; non servono a rendere automaticamente sicuri o immutabili i dati.

Leggi un nome scritto nella pagina

Finora lo script conosce solo i clic. Aggiungi un campo in index.html, prima del pulsante. L’etichetta dice a cosa serve il campo e for="nome" lo collega all’id dell’input.

<label for="nome">Il tuo nome</label>
<input id="nome" type="text">

Un input espone il testo digitato tramite value. trim() toglie gli spazi all’inizio e alla fine; !== "" chiede se il testo rimasto è diverso da una stringa vuota. Sostituisci script.js con questa versione completa. Prima di comporre il messaggio, legge il campo; se è vuoto, mostra solo il conteggio.

const pulsante = document.querySelector("#pulsante");
const risultato = document.querySelector("#risultato");
const campoNome = document.querySelector("#nome");
let clic = 0;

function messaggioPer(numeroClic) {
  if (numeroClic === 3) {
    return "Hai raggiunto tre clic!";
  }
  return "Clic: " + numeroClic;
}

pulsante.addEventListener("click", () => {
  clic = clic + 1;
  const nome = campoNome.value.trim();
  if (nome !== "") {
    risultato.textContent = "Ciao, " + nome + ". " + messaggioPer(clic);
  } else {
    risultato.textContent = messaggioPer(clic);
  }
});

Ricarica, scrivi “Ada” e premi: leggi “Ciao, Ada. Clic: 1”. Cancella il nome e premi di nuovo: leggi solo il conteggio. value legge il testo corrente del campo; trim() toglie gli spazi alle estremità; !== "" chiede se rimane un testo non vuoto. nome nasce dentro il listener e viene riletto a ogni clic.

textContent mostra ciò che scrivi come testo, senza interpretarlo come HTML. Prova a inserire <b>Ada</b> nel campo: vedrai i caratteri, non un nome in grassetto.

Eventi oltre il clic

addEventListener collega una funzione a un evento; il browser la chiama quando l’evento accade. La funzione è un callback. input arriva mentre cambia il campo; change segnala una modifica confermata; submit riguarda l’invio di un modulo.

const campo = document.querySelector("#nome");
const anteprima = document.querySelector("#anteprima");
campo.addEventListener("input", () => {
  anteprima.textContent = campo.value;
});

Qui l’anteprima segue ciò che digiti. Per inviare un modulo con JavaScript, avvolgi campo e pulsante in un elemento form e aggiungi un paragrafo per il messaggio:

<form id="saluto-form">
  <label for="nome">Il tuo nome</label>
  <input id="nome" type="text">
  <button type="submit">Invia</button>
</form>
<p id="risposta-form"></p>

Ascolta l’evento submit. Il callback riceve un oggetto evento; evento.preventDefault() ferma l’invio tradizionale del browser quando JavaScript gestirà la pagina:

const modulo = document.querySelector("#saluto-form");
const campoNome = document.querySelector("#nome");
const rispostaForm = document.querySelector("#risposta-form");

modulo.addEventListener("submit", (evento) => {
  evento.preventDefault();
  rispostaForm.textContent = `Ciao ${campoNome.value.trim()}`;
});

Dopo aver fermato l’invio, mostra un esito chiaro: non lasciare il pulsante senza risposta. La tastiera può generare gli stessi eventi: l’invio con Invio deve funzionare quanto il clic sul pulsante.

Un listener per tutta la lista

Un evento attraversa prima gli antenati verso il bersaglio nella fase di cattura e poi risale dal bersaglio verso gli antenati nella fase di propagazione (bubbling). Per impostazione predefinita il listener viene eseguito durante la risalita; il terzo argomento di addEventListener può richiedere la cattura. Un clic su un pulsante può quindi arrivare anche al suo contenitore. Per questo un listener sul contenitore può gestire i clic di molti elementi figli, anche se vengono aggiunti dopo. Questa tecnica si chiama delegazione degli eventi.

const elenco = document.querySelector("#voci");
elenco.addEventListener("click", (evento) => {
  const pulsante = evento.target.closest("button[data-azione]");
  if (!pulsante || !elenco.contains(pulsante)) return;
  console.log("Azione:", pulsante.dataset.azione);
});

event.target è l’elemento da cui è partito l’evento; event.currentTarget è l’elemento che sta eseguendo questo listener. closest cerca il pulsante più vicino che corrisponde al selettore. La delegazione evita un listener per ogni voce. Se serve fermare la propagazione esiste stopPropagation(), ma usalo solo quando vuoi davvero impedire ad altri contenitori di reagire.

Moduli e validazione dei dati

Gli input possono essere vuoti o contenere valori non validi. Leggi il testo, rimuovi spazi esterni e controlla il numero prima di usarlo. Una stringa vuota convertita con Number() diventa zero; testo non numerico diventa NaN.

const testo = campoObiettivo.value.trim();
const obiettivo = Number(testo);
if (testo === "") {
  risultato.textContent = "Inserisci un valore";
} else if (!Number.isFinite(obiettivo) || obiettivo < 1) {
  risultato.textContent = "Inserisci un numero maggiore di zero";
} else {
  risultato.textContent = `Obiettivo: ${obiettivo}`;
}

Number.isFinite esclude NaN e gli infiniti. Il controllo sul testo distingue un campo vuoto dallo zero valido. HTML offre anche required, min e max, ma il codice deve comunque gestire i dati ricevuti. Prova campo vuoto, zero, lettere e un numero valido; il risultato atteso è un messaggio diverso per input non valido e valido.

Ora prova tu: aggiungi Azzera

Prima di proseguire, aggiungi un secondo pulsante sotto quello del contatore. Il risultato atteso è preciso: due clic sul primo pulsante, “Azzera”, un altro clic devono mostrare 1, 2, 0, 1. Il nome può restare nel campo.

<button id="azzera" type="button">Azzera</button>

In script.js devi trovare il nuovo pulsante, ascoltare il suo clic, assegnare 0 a clic e aggiornare il testo. Prova prima da solo: sai già usare querySelector, addEventListener, = e textContent.

Mostra una soluzione possibile

Aggiungi questo blocco in fondo a script.js:

const pulsanteAzzera = document.querySelector("#azzera");
pulsanteAzzera.addEventListener("click", () => {
  clic = 0;
  risultato.textContent = "Clic: 0";
});

Il reset cambia sia il valore conservato in clic sia il testo visibile. Cambiare solo il testo farebbe ricomparire il vecchio conteggio al clic successivo.

Un numero scritto in un campo è ancora testo

Un campo HTML restituisce una stringa anche con type="number". Questo conta quando vuoi scegliere un obiettivo: "3" + 1 produce "31", mentre Number("3") + 1 produce 4. Prova entrambe le espressioni nella Console prima di continuare.

In index.html, dopo il paragrafo del risultato, aggiungi un campo, un pulsante di verifica e un paragrafo per la risposta:

<label for="obiettivo">Obiettivo di clic</label>
<input id="obiettivo" type="number" min="1" step="1">
<button id="controlla" type="button">Controlla obiettivo</button>
<p id="verifica" aria-live="polite"></p>

Il nuovo codice usa Number() per trasformare il testo del campo in numero. Prima controlla che non sia vuoto e che Number.isInteger() confermi un intero maggiore di zero. || significa “oppure”: basta un problema per mostrare la richiesta di correzione. ! inverte un valore booleano. Se il dato è valido, else if controlla se clic >= obiettivo, cioè se il conteggio è maggiore o uguale all’obiettivo; else calcola i clic mancanti. In fondo a script.js, dopo il reset, aggiungi questo blocco:

const campoObiettivo = document.querySelector("#obiettivo");
const pulsanteControlla = document.querySelector("#controlla");
const verifica = document.querySelector("#verifica");

pulsanteControlla.addEventListener("click", () => {
  const testo = campoObiettivo.value.trim();
  const obiettivo = Number(testo);
  if (testo === "" || !Number.isInteger(obiettivo) || obiettivo < 1) {
    verifica.textContent = "Scrivi un numero intero maggiore di zero.";
  } else if (clic >= obiettivo) {
    verifica.textContent = "Obiettivo raggiunto!";
  } else {
    verifica.textContent = "Clic mancanti: " + (obiettivo - clic) + ".";
  }
});

Scrivi 3, fai due clic sul contatore e premi “Controlla obiettivo”: leggi “Clic mancanti: 1.”. Dopo un altro clic, leggi “Obiettivo raggiunto!”. Con campo vuoto o 0 compare il messaggio di correzione. Number() converte il testo; Number.isInteger() controlla che sia un intero; || significa “oppure” e basta una condizione non valida per entrare nel primo blocco. ! inverte una risposta booleana; >= significa “maggiore o uguale”.

Non eliminare il controllo sul campo vuoto: Number("") vale 0. Cambia l’obiettivo in 5 e verifica che il numero di clic mancanti cambi. Qui stai verificando un dato inserito da una persona prima di usarlo in un calcolo.

Una lista di valori: l’array

Finora hai usato un valore alla volta. Per conservare più traguardi in ordine, usa un array. Le parentesi quadre creano la lista; le virgole separano gli elementi. Ogni posizione ha un indice che parte da 0: traguardi[0] legge il primo valore. length indica quanti elementi ci sono. Prova questo blocco nella Console: non va copiato in script.js.

{
  const traguardi = [3, 5, 10];
  console.log(traguardi[0]);      // 3
  console.log(traguardi[1]);      // 5
  console.log(traguardi.length);  // 3
  traguardi.push(15);
  console.log(traguardi.length);  // 4
  console.log(traguardi.includes(5)); // true
}

L’indice del primo elemento è 0, quello del secondo è 1. length indica quanti elementi ci sono. push(15) aggiunge un valore in fondo, perciò la seconda lettura di length vale 4. includes(5) restituisce true, perché 5 è nella lista. Cambia 5 in 8 nella chiamata a includes e riesegui l’intero blocco: vedrai false.

const impedisce di assegnare un nuovo array al nome traguardi, ma push può modificare l’array esistente. Se vuoi una lista che non cambi, evita di chiamare metodi che la modificano. Un array è utile quando l’ordine conta o quando farai la stessa operazione su più elementi.

Metodi degli array: map, filter e find

for...of visita gli elementi uno alla volta. Altri metodi descrivono direttamente il risultato: map trasforma ogni elemento in un nuovo array; filter conserva quelli che rispettano una condizione; find restituisce il primo che la rispetta.

const traguardi = [3, 5, 10];
const testi = traguardi.map((n) => `A ${n} clic`);
const grandi = traguardi.filter((n) => n >= 5);
const prossimo = traguardi.find((n) => n > 3);
console.log(testi, grandi, prossimo);

La funzione passata riceve ogni elemento; quella di filter deve restituire un valore truthy per tenerlo. find restituisce undefined se non c’è corrispondenza. Questi metodi non modificano l’array iniziale; push invece lo modifica. Scegli il metodo dal risultato richiesto e verifica se cambia i dati condivisi.

Scegli il metodo giusto per una lista

map, filter e find rispondono a domande diverse. forEach esegue un’azione per ogni elemento e non crea una nuova lista trasformata. some chiede se almeno un elemento soddisfa una condizione; every se la soddisfano tutti.

const clic = [1, 2, 3, 4];
const doppi = clic.map((numero) => numero * 2);
const pari = clic.filter((numero) => numero % 2 === 0);
const neEsisteUnoGrande = clic.some((numero) => numero > 3);
const tuttiPositivi = clic.every((numero) => numero > 0);
const totale = clic.reduce((somma, numero) => somma + numero, 0);

reduce accumula i valori in un risultato; qui parte da 0 e aggiunge ogni numero. Usalo quando l’accumulazione rende il codice più chiaro, non solo per sostituire ogni ciclo. sort modifica l’array originale e, senza comparatore, ordina i valori come testo. Per numeri usa numeri.sort((a, b) => a - b); se vuoi preservare l’array iniziale, copia prima o usa toSorted nei browser che lo supportano.

Map e Set per altri tipi di raccolta

Array e oggetti coprono molti casi, ma JavaScript offre raccolte con regole diverse. Un Set conserva valori unici; una Map associa chiavi e valori e può usare come chiave anche un oggetto.

const visti = new Set(["it", "en", "it"]);
visti.add("fr");
console.log(visti.has("en"), visti.size); // true, 3
const conteggi = new Map();
conteggi.set("clic", 3);
console.log(conteggi.get("clic")); // 3

Usa un array quando l’ordine e la ripetizione degli elementi contano. Un oggetto è adatto a un gruppo di proprietà nominate; una Map è comoda per associazioni dinamiche o chiavi non testuali. Non devi scegliere una raccolta “più avanzata”: scegli quella che rende esplicita la regola dei dati.

Dare un nome ai dati: l’oggetto

Una soglia da sola non racconta tutto. Un oggetto raggruppa dati con nomi, detti proprietà. Qui un traguardo ha una soglia e una descrizione; le graffe creano l’oggetto e i due punti separano nome e valore. Il punto legge una proprietà: traguardo.soglia sarà un numero, traguardo.testo una stringa.

{
  const traguardo = { soglia: 3, testo: "Primo traguardo" };
  console.log(traguardo.soglia); // 3
  console.log(traguardo.testo);  // Primo traguardo
  console.log(traguardo["soglia"]); // 3
  traguardo.soglia = 5;
  console.log(traguardo.soglia); // 5
}

Il punto legge una proprietà: traguardo.soglia è un numero, traguardo.testo è una stringa. Puoi anche scrivere traguardo["soglia"], utile quando il nome della proprietà arriva da una variabile. Per cambiare una proprietà puoi assegnare traguardo.soglia = 5. Come per gli array, const protegge il nome dalla riassegnazione, non congela il contenuto dell’oggetto.

Un array e un oggetto risolvono bisogni diversi: l’array tiene una sequenza; l’oggetto dà un nome ai pezzi di un dato. Per più traguardi completi puoi mettere diversi oggetti dentro un array. Ora li userai per costruire una lista visibile.

Estrarre valori da array e oggetti

La destrutturazione assegna proprietà o posizioni di un array a nomi distinti. Riduce ripetizioni quando un dato strutturato ti serve in più punti.

const persona = { nome: "Ada", clic: 3 };
const { nome, clic: totaleClic } = persona;
const [primo, secondo] = ["inizio", "continua"];
console.log(nome, totaleClic, primo, secondo);

Nell’oggetto puoi rinominare una proprietà con clic: totaleClic. Nell’array conta invece la posizione: primo riceve l’elemento con indice zero. Se una proprietà potrebbe mancare, puoi fornire un valore predefinito con const { tema = "chiaro" } = preferenze;. La destrutturazione legge i valori: non cancella le proprietà dall’oggetto.

Proprietà, metodi e this

Un oggetto può contenere funzioni: una funzione in una proprietà si chiama metodo. Le proprietà descrivono dati; i metodi descrivono operazioni su quei dati.

const contatore = {
  clic: 0,
  aumenta() {
    this.clic += 1;
    return this.clic;
  }
};
console.log(contatore.aumenta()); // 1

In contatore.aumenta(), this indica l’oggetto che riceve la chiamata. Se estrai il metodo e lo chiami da solo, il contesto può cambiare. Le funzioni freccia non hanno un proprio this, perciò qui usiamo la sintassi di metodo. Per un solo dato strutturato basta un oggetto; quando vuoi creare molte istanze con la stessa forma puoi usare una classe.

Classi e istanze

Una class descrive una forma condivisa per creare oggetti; ogni oggetto creato è un’istanza. constructor imposta i dati iniziali e new crea una nuova istanza.

class Contatore {
  constructor(nome) {
    this.nome = nome;
    this.clic = 0;
  }
  aumenta() { this.clic += 1; }
}
const primo = new Contatore("A");
const secondo = new Contatore("B");
primo.aumenta();
console.log(primo.clic, secondo.clic); // 1, 0

Ogni istanza condivide i metodi ma mantiene i propri dati. Le classi sono utili quando questa struttura si ripete; per un singolo oggetto spesso basta { nome: "A" }. Questa guida introduce la sintassi delle classi e il collegamento con i prototipi. L’ereditarietà è un approfondimento successivo: non serve per usare classi semplici.

Raccogliere il resto e copiare i valori

I tre puntini cambiano ruolo in base al punto in cui compaiono. Nella destrutturazione raccolgono gli elementi rimasti con rest; in un array, in un oggetto o in una chiamata espandono gli elementi con spread.

const [primo, ...altri] = ["a", "b", "c"];
const base = { tema: "chiaro", lingua: "it" };
const preferenze = { ...base, lingua: "en" };
function mostra(primo, ...resto) {
  console.log(primo, resto);
}
mostra("inizio", "esempio", "fine");

resto raccoglie gli argomenti dopo il primo; preferenze è un nuovo oggetto con i valori di base e la lingua aggiornata. Lo spread crea però una copia superficiale: se una proprietà contiene un altro oggetto o array, quel valore interno resta condiviso. Per questo spread non risolve da solo tutti i problemi dei riferimenti.

Da dove arrivano i metodi degli oggetti?

Gli oggetti JavaScript possono delegare la ricerca di una proprietà a un altro oggetto collegato, il loro prototipo. Se non trova una proprietà sull’oggetto, JavaScript la cerca lungo questa catena. È così che, per esempio, un array può usare metodi condivisi come map.

const colori = ["blu", "giallo"];
console.log(Object.getPrototypeOf(colori) === Array.prototype); // true
console.log(typeof colori.map); // "function"

class Promemoria {
  constructor(testo) { this.testo = testo; }
  descrivi() { return `Promemoria: ${this.testo}`; }
}

Il metodo descrivi è condiviso dal prototipo della classe, mentre testo appartiene a ogni istanza. Le classi forniscono una sintassi più familiare per creare oggetti collegati da questa catena. Per iniziare, usa class quando più istanze condividono comportamento; di norma non serve modificare direttamente prototype.

Quando una proprietà potrebbe mancare

Se un dato può non esserci, accedere direttamente a una sua proprietà può generare un errore. L’optional chaining (?.) interrompe la lettura e restituisce undefined quando il valore a sinistra è null o undefined.

const profilo = { nome: "Ada" };
const citta = profilo.indirizzo?.citta;
const nomeVisualizzato = profilo.nome ?? "Ospite";
console.log(citta, nomeVisualizzato); // undefined, "Ada"

?? usa il valore di destra solo se quello di sinistra è null o undefined. A differenza di ||, mantiene valori validi come 0, false e "". Questi operatori rendono più semplice gestire dati facoltativi, ma non sostituiscono la verifica dei dati che arrivano dall’esterno.

Copiare array e oggetti: valori e riferimenti

Quando assegni un numero a un nuovo nome, il nome riceve quel valore. Con array e oggetti, invece, una semplice assegnazione crea un secondo nome per lo stesso oggetto: modificarlo attraverso uno dei due nomi si vede anche dall’altro.

const primo = [3, 5];
const alias = primo;
alias.push(10);
console.log(primo); // [3, 5, 10]

const copia = [...primo];
copia.push(12);
console.log(primo); // [3, 5, 10]
console.log(copia); // [3, 5, 10, 12]

La sintassi [...primo] crea un nuovo array superficiale. Anche per gli oggetti puoi usare { ...impostazioni }. “Superficiale” significa che i valori annidati restano condivisi: se l’oggetto contiene un altro oggetto, questa copia non lo duplica in profondità. Capire se stai modificando dati condivisi è utile per spiegare cambiamenti che sembrano apparire in più punti del programma.

Ripetere senza copiare lo stesso codice

Se hai tre traguardi, potresti scrivere tre condizioni separate. Un ciclo esegue lo stesso lavoro per ogni elemento di un array. for...of prende un elemento alla volta. Aggiungi in index.html, dopo gli elementi dell’obiettivo:

<button id="mostra-traguardi" type="button">Mostra traguardi</button>
<ul id="lista-traguardi" aria-label="Traguardi raggiunti"></ul>

Quando premi il nuovo pulsante, replaceChildren() svuota la lista, poi il ciclo la ricostruisce. Per ogni soglia raggiunta, createElement("li") crea una voce, textContent le dà un testo e append la inserisce nella lista. Con cinque clic vedrai due voci. In fondo a script.js, dopo la verifica dell’obiettivo, aggiungi:

const traguardi = [
  { soglia: 3, testo: "Primo traguardo" },
  { soglia: 5, testo: "Secondo traguardo" },
  { soglia: 10, testo: "Terzo traguardo" }
];
const pulsanteTraguardi = document.querySelector("#mostra-traguardi");
const listaTraguardi = document.querySelector("#lista-traguardi");

pulsanteTraguardi.addEventListener("click", () => {
  listaTraguardi.replaceChildren();
  for (const traguardo of traguardi) {
    if (clic >= traguardo.soglia) {
      const voce = document.createElement("li");
      voce.textContent = traguardo.testo;
      listaTraguardi.append(voce);
    }
  }
});

Ricarica, fai cinque clic sul contatore e premi “Mostra traguardi”: leggi due voci. Premi “Azzera” e poi di nuovo “Mostra traguardi”: la lista torna vuota. for...of visita ogni oggetto; if controlla se la soglia è stata raggiunta. createElement("li") crea una voce, append la inserisce nella lista. replaceChildren() elimina le voci precedenti prima di ricostruirle: per questo il reset scritto prima resta valido.

Prova ad aggiungere un quarto oggetto con soglia 12. Non devi aggiungere un quarto if: il ciclo lo considererà da solo. Questa è la differenza pratica tra una lista di dati e istruzioni copiate più volte.

Cicli for e while

for...of è adatto a visitare un array. Il for classico è utile quando serve l’indice: contiene valore iniziale, condizione e aggiornamento. while ripete finché la condizione resta vera.

const traguardi = [3, 5, 10];
for (let indice = 0; indice < traguardi.length; indice += 1) {
  console.log(indice, traguardi[indice]);
}
let attesa = 3;
while (attesa > 0) {
  attesa -= 1;
}

Gli indici iniziano da zero e l’ultimo è length - 1. Nel ciclo while aggiorna il valore controllato: senza una modifica la condizione potrebbe restare vera per sempre. break termina il ciclo e continue salta al giro successivo; usali se rendono la regola più chiara.

Persistenza: localStorage e JSON

Le variabili si azzerano quando chiudi la pagina. localStorage conserva stringhe tra visite. Per numeri e strutture converti il valore: JSON.stringify prepara una stringa JSON e JSON.parse la ricostruisce.

const impostazioni = { clic: 3, tema: "chiaro" };
localStorage.setItem("impostazioni", JSON.stringify(impostazioni));
const testo = localStorage.getItem("impostazioni");
const lette = testo === null ? null : JSON.parse(testo);
console.log(lette?.clic); // 3

Una chiave assente restituisce null; ?. legge una proprietà soltanto se il valore non è null o undefined. In un progetto reale gestisci anche dati salvati malformati, che possono far fallire JSON.parse. Non conservare password o dati privati: chi usa il browser può leggere questo spazio. La persistenza è una scelta del progetto, non un requisito per il contatore.

JSON non è ancora un oggetto JavaScript

JSON.stringify converte dati JavaScript in testo JSON; JSON.parse fa il percorso inverso e può lanciare un errore se il testo non è JSON valido. localStorage conserva stringhe, quindi la conversione è necessaria quando salvi oggetti.

const testo = '{"clic":3}';
try {
  const dato = JSON.parse(testo);
  if (typeof dato.clic === "number") {
    console.log(dato.clic);
  }
} catch (errore) {
  console.error("Il testo salvato non è JSON valido", errore);
}

Un JSON valido può comunque contenere campi mancanti o tipi diversi da quelli attesi. Dopo il parsing, controlla la forma dei dati prima di usarli: la sintassi valida non garantisce che il contenuto sia adatto al tuo programma. JSON non conserva funzioni, metodi, undefined o tutti i dettagli degli oggetti JavaScript.

Leggi gli errori prima di cambiare codice

Se un clic non produce il risultato previsto, apri la Console. Controlla se script.js è nella stessa cartella dell’HTML, se hai salvato e ricaricato e se gli ID nei due file coincidono. Un errore rosso indica spesso il file e la riga da cui iniziare. Puoi mettere temporaneamente console.log(clic) nel listener per vedere se il conteggio cambia.

Un elemento mancante è un caso prevedibile. querySelector restituisce null; prima di usare l’elemento puoi controllarlo:

{
  const elemento = document.querySelector("#inesistente");
  if (elemento === null) {
    console.log("Elemento non trovato");
  }
}

Altre operazioni possono fallire anche se hai scritto bene il codice, per esempio una richiesta di rete. try/catch permette di reagire all’errore: le istruzioni in try vengono tentate; se un errore viene segnalato, catch lo riceve. Qui throw new Error(...) crea e segnala un errore apposta per la prova. Incolla il blocco nella Console e leggi il messaggio.

try {
  throw new Error("Prova di errore");
} catch (errore) {
  console.log(errore.message); // Prova di errore
}

Non usare try/catch per nascondere un ID scritto male: correggi l’ID. Tieni la Console aperta mentre fai gli esercizi; ti aiuta a distinguere “il codice non è partito” da “il codice è partito ma ha usato un valore sbagliato”.

Gestire un errore quando puoi recuperare

try...catch intercetta un errore lanciato nel blocco try e ti permette di mostrare un messaggio o scegliere un recupero nel blocco catch. Non avvolgere tutto il programma: intercetta vicino all’operazione che può fallire e quando hai una risposta utile da dare.

function leggiImpostazioni() {
  try {
    const testo = localStorage.getItem("impostazioni");
    return testo ? JSON.parse(testo) : {};
  } catch (errore) {
    console.error("Impostazioni non leggibili", errore);
    return {};
  }
}

Gli errori di sintassi impediscono al file di essere interpretato; gli errori di riferimento indicano spesso un nome inesistente; quelli di tipo segnalano un’operazione non valida per quel valore; un errore logico può invece produrre un risultato sbagliato senza avvisi. Nella Console leggi prima il tipo e la riga indicata, poi verifica i valori con console.log o un punto di interruzione nel pannello Sources. Correggi una causa alla volta.

Quando il risultato arriva più tardi

Il listener reagisce a un clic futuro. Anche un timer o una richiesta di rete finisce più tardi. Per vedere l’attesa senza dipendere da un server, aggiungi in index.html:

<button id="attendi" type="button">Avvia attesa</button>
<p id="stato-attesa" aria-live="polite">Pronto.</p>

setTimeout programma un’azione futura. new Promise(...) crea un valore che rappresenta un risultato non ancora arrivato: il timer chiamerà risolvi dopo l’intervallo indicato per segnalare che l’attesa è finita. async permette alla funzione di usare await per aspettare quel risultato. L’attesa sospende quella funzione, mentre la pagina resta utilizzabile. In fondo a script.js, aggiungi:

const pulsanteAttendi = document.querySelector("#attendi");
const statoAttesa = document.querySelector("#stato-attesa");

function aspetta(millisecondi) {
  return new Promise((risolvi) => {
    setTimeout(risolvi, millisecondi);
  });
}

pulsanteAttendi.addEventListener("click", async () => {
  statoAttesa.textContent = "Attendo...";
  await aspetta(1000);
  statoAttesa.textContent = "Attesa finita.";
});

Premi “Avvia attesa”: vedi subito “Attendo...” e dopo circa un secondo “Attesa finita.”. Durante l’attesa il contatore risponde ancora ai clic. setTimeout programma un’azione futura; una Promise rappresenta il risultato che arriverà. async permette di usare await: questa funzione si sospende finché la Promise non termina, mentre il resto della pagina continua a funzionare.

Una richiesta con fetch() restituisce anch’essa una Promise, ma richiede un indirizzo che risponda davvero. Ora hai visto il meccanismo su una prova che funziona aprendo i tuoi file. Per usare dati da un server dovrai anche controllare la risposta e gestire gli errori.

Perché il codice asincrono arriva dopo

JavaScript esegue le istruzioni sincrone una alla volta. Quando incontra un timer o una richiesta, il browser si occupa dell’attesa; nel frattempo lo script può continuare. Quando il risultato è pronto, il browser programma il lavoro da eseguire appena il codice corrente termina.

console.log("inizio");
setTimeout(() => console.log("timer"), 0);
Promise.resolve().then(() => console.log("promise"));
console.log("fine");

L’ordine osservato è inizio, fine, promise, timer. Il callback di una Promise viene messo nella coda dei microtask, elaborata prima dei callback dei timer. Non serve imparare subito ogni dettaglio della coda: ricorda che “attesa pari a zero” non significa “esegui ora”. Le funzioni sincrone lunghe, invece, bloccano la pagina finché non terminano.

Comporre più attese

await rende leggibile l’attesa di una singola Promise. Se hai più lavori indipendenti, puoi avviarli insieme con Promise.all e aspettare i risultati; se uno fallisce, l’insieme viene rifiutato. Se invece vuoi conservare anche i risultati degli altri, esiste Promise.allSettled.

async function caricaPagina() {
  try {
    const [utente, preferenze] = await Promise.all([
      fetch("/api/utente").then((risposta) => risposta.json()),
      fetch("/api/preferenze").then((risposta) => risposta.json())
    ]);
    console.log(utente, preferenze);
  } catch (errore) {
    console.error("Almeno una richiesta non è riuscita", errore);
  }
}

Le due richieste partono senza aspettare l’una l’altra. Con due await consecutivi, la seconda partirebbe solo dopo la prima se la Promise viene creata lì. Scegli la sequenza quando un risultato serve per avviare il passaggio seguente; scegli l’esecuzione parallela quando i lavori non dipendono tra loro. In una richiesta reale controlla anche risposta.ok: fetch non rifiuta automaticamente la Promise per una risposta HTTP come 404.

Fetch e richieste asincrone

Un timer termina più tardi; anche una richiesta con fetch restituisce una Promise, un valore che rappresenta un risultato futuro. La risposta HTTP e il suo contenuto sono passaggi diversi:

async function caricaDati() {
  try {
    const risposta = await fetch("https://example.com/dati.json");
    if (!risposta.ok) throw new Error(`HTTP ${risposta.status}`);
    const dati = await risposta.json();
    console.log(dati);
  } catch (errore) {
    console.error("Richiesta non riuscita", errore);
  }
}

L’URL è un segnaposto da sostituire con un indirizzo reale che restituisca JSON e consenta la richiesta. fetch può completarsi anche con stato 404, quindi controlla risposta.ok. await aspetta la risposta e poi la conversione JSON; durante l’attesa il browser continua a rispondere. try/catch permette di gestire errori di rete o di lettura. Per provare richieste reali avvia un server locale: l’apertura diretta con file:// non equivale a servire un sito.

Moduli: import ed export

Quando script.js cresce, puoi spostare funzioni in altri file. export rende disponibile una funzione; import la usa. Ogni modulo ha il proprio spazio dei nomi.

// messaggi.js
export function messaggioPer(clic) {
  return `Clic: ${clic}`;
}
// script.js
import { messaggioPer } from "./messaggi.js";
console.log(messaggioPer(3));

In HTML carica il punto di partenza con <script type="module" src="script.js">. Le parentesi graffe indicano un export nominato e il nome deve corrispondere. I moduli usano percorsi relativi al file importatore e il browser li carica via HTTP, quindi per questa struttura serve un server di sviluppo. Dividi il progetto quando i file separati rendono più chiaro chi si occupa di ogni parte; non serve un modulo per ogni funzione.

Annotare una scelta nel file

Un commento è una nota per chi legge il codice: JavaScript non la esegue. // avvia un commento di una riga; /* ... */ ne racchiude uno su più righe. Hai già visto commenti negli esempi della Console, dove indicavano il risultato atteso.

// Questi ID devono corrispondere a quelli in index.html.
const pulsante = document.querySelector("#pulsante");
const risultato = document.querySelector("#risultato");

Puoi aggiungere questa nota sopra le prime due righe di script.js: ricaricando, la pagina funziona come prima. Scrivi un commento quando spiega una scelta o una dipendenza tra file; non serve ripetere in parole ciò che ogni istruzione dice già.

Rileggi il progetto senza saltare passaggi

Rileggi il progetto in ordine: l’HTML crea elementi; il DOM li rende trovabili; un listener aspetta un evento; una variabile conserva lo stato; operatori e condizioni scelgono cosa fare; una funzione prepara un risultato; JavaScript aggiorna la pagina. I campi forniscono testo: ripuliscilo, converti solo quando serve e convalida il valore.

Array e oggetti organizzano insiemi di dati; metodi e cicli li trasformano; riferimenti e copie spiegano quando una modifica è condivisa. Classi creano istanze con struttura simile. I moduli separano i file. Timer e fetch mostrano risultati asincroni: controlla risposte ed errori. localStorage conserva stringhe tra visite. Sono concetti diversi, ciascuno introdotto nel proprio capitolo.
