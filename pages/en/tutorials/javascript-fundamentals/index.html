Your first click

Press the button. Watch what changes.

Here JavaScript has one clear job: wait for a click and change a sentence on the page. Before clicking, you will read “No clicks yet.”; afterwards, “You pressed the button!”. Try it and watch the response.

The button and sentence are HTML elements. JavaScript connects the action on the button to the change in the sentence. In the next steps, you will use the same idea to count clicks, choose a response and read a name entered on the page.

The page in the browserWaiting

No clicks yet.

To make this example yourself, you need a browser and a code editor such as Visual Studio Code: edit the files, save and check the result in the browser. If HTML buttons and attributes are still unfamiliar, start with the HTML guide.

Follow the project through the Reset button. Then use the final sections when you want to explore more of the language. If the button here is unavailable, the examples and instructions in the chapters remain readable.

Bring the first click into your files

Create a folder named js-practice and open it in your editor. Create index.html and script.js inside it. Write this in index.html:

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>My first JavaScript experiment</title>
  <script src="script.js" defer></script>
</head>
<body>
  <h1>My first experiment</h1>
  <button id="button" type="button">Show message</button>
  <p id="result" aria-live="polite">No clicks yet.</p>
</body>
</html>

Write this in script.js:

const button = document.querySelector("#button");
const result = document.querySelector("#result");

button.addEventListener("click", () => {
  result.textContent = "You pressed the button!";
});

Save both files and open index.html in a browser. Before clicking, you see “No clicks yet.”; after clicking, you see “You pressed the button!”. Change the quoted text in script.js, save and reload: the new message will appear on the next click.

src="script.js" points to the file in the same folder. defer runs this script after the browser has parsed the HTML: the button already exists when JavaScript looks for it. If nothing happens, check the filename and look for an error in the browser console.

Follow the click through the code

document.querySelector("#button") finds the element with id="button". The # follows CSS selector syntax. The second line finds the paragraph. const names each element so you can use it later.

addEventListener("click", ...) registers a function to run when a click arrives. The instructions between { and } do not run right away. On a click, textContent replaces the paragraph text. This is the DOM: the page structure that JavaScript can read and change.

Try changing #result to #missing and reload. Clicking no longer works: the selector finds no element, so result is null. Restore #result. The name in HTML and the one in your script must match.

For an element with an ID, you can also use document.getElementById("result"). Here we use querySelector because it also accepts class and element selectors.

Let the page remember clicks

The message is always the same. Now we want to count button presses. Replace everything in script.js with this:

const button = document.querySelector("#button");
const result = document.querySelector("#result");
let clicks = 0;

button.addEventListener("click", () => {
  clicks = clicks + 1;
  result.textContent = `Clicks: ${clicks}`;
});

Reload and press three times: you see “Clicks: 1”, then “Clicks: 2”, then “Clicks: 3”. let creates a variable you reassign on every click. const works for button and result because you do not assign them another element. The text between backticks is a template string: ${clicks} inserts the current value.

Reloading the page resets the count to zero: this variable exists only while the current page is open.

Change the response on the third click

On the third click, we want a different message. Keep the first three lines and replace the whole button.addEventListener(...) block:

button.addEventListener("click", () => {
  clicks = clicks + 1;
  if (clicks === 3) {
    result.textContent = "You reached three clicks!";
  } else {
    result.textContent = `Clicks: ${clicks}`;
  }
});

Reload: the first two clicks show the number; the third shows the special message; the fourth shows “Clicks: 4”. if checks a condition. === compares without automatically converting different types: the number 3 differs from the text "3". else handles the other cases.

Give the decision a name

The decision about the text can have a name. Replace script.js with this complete version:

const button = document.querySelector("#button");
const result = document.querySelector("#result");
let clicks = 0;

function messageFor(clickCount) {
  if (clickCount === 3) {
    return "You reached three clicks!";
  }
  return `Clicks: ${clickCount}`;
}

button.addEventListener("click", () => {
  clicks = clicks + 1;
  result.textContent = messageFor(clicks);
});

Reload and repeat four clicks: the result is the same as in the previous chapter. messageFor receives a number as a parameter and returns text with return. The click function uses that text to update the page. Separating the message decision from the browser action makes both easier to check.

Bring a name into the message

Add a field for a name. In index.html, immediately before the button, insert:

<label for="name">Your name</label>
<input id="name" type="text" autocomplete="name">

Now replace script.js with this version. The message function stays the same; the click reads the field and adds a greeting when it contains text:

const button = document.querySelector("#button");
const result = document.querySelector("#result");
const nameField = document.querySelector("#name");
let clicks = 0;

function messageFor(clickCount) {
  if (clickCount === 3) {
    return "You reached three clicks!";
  }
  return `Clicks: ${clickCount}`;
}

button.addEventListener("click", () => {
  clicks = clicks + 1;
  const name = nameField.value.trim();
  const greeting = name ? `Hello, ${name}. ` : "";
  result.textContent = greeting + messageFor(clicks);
});

Reload, type “Ada” and press the button: you see “Hello, Ada. Clicks: 1”. Leave the field empty and you see just the count. value reads what you typed; trim() removes spaces at either end. condition ? value1 : value2 chooses between two pieces of text. textContent displays the name as text without interpreting it as HTML: enter <b>Ada</b> to see this.

When a click does not give the expected result

Open your browser developer tools and the Console tab. If the page does not react, check in order: is script.js in the same folder? Do the HTML IDs match the querySelector calls? Did you save and reload?

You can temporarily add console.log(clicks); after clicks = clicks + 1;. Each button press should print 1, 2, 3 in the Console. The log appears in the tools, not on the page. Remove the line when done. A red error with a line number shows where to start looking; a click without a log suggests checking the file connection or listener.

Your turn: add Reset

Goal: after some clicks, the “Reset” button should put the count back to zero and show “Clicks: 0”. The name field can stay as it is. First, add a second button below the existing one in index.html:

<button id="reset" type="button">Reset</button>

In the JS file, find that button, listen for its click, assign 0 to clicks and update result.textContent. Try this sequence: two clicks on the first button, reset, one more click. The text should show 1, 2, 0, 1. This checks that the state really reset.

Show one possible solution

Append this to your existing script.js; it is not a new file:

const resetButton = document.querySelector("#reset");

resetButton.addEventListener("click", () => {
  clicks = 0;
  result.textContent = "Clicks: 0";
});

The reset changes the same variable used by the first button. If you change only the visible text, the old count returns on the next click.

Five questions to guide you through the code

Where is the element?
document.querySelector("#id"); for an ID you can also use document.getElementById("id").
When does the code run?
addEventListener("click", function) reacts to a browser event.
Which value changes?
let for a value you reassign; const when you do not reassign the name.
How do you choose the result?
if and === check a condition; return returns a function result.
How do you update the page?
textContent writes text into an element; value reads a field.

Check what you have understood

Ten questions about the examples in this guide. Each answer includes an explanation.

Leave a note in the file

A comment explains a choice in the file; the browser does not execute it. Use // for one line or /* and */ for several. For example, above the two selections you can note why they must match the HTML:

// These IDs must match the ones in index.html.
const button = document.querySelector("#button");
const result = document.querySelector("#result");

Add the comment and reload: the page behaves exactly as before. You do not need to comment on every instruction; here you are recording a dependency between two files.

When you have more than one value

To collect several milestones, an array keeps an ordered list; an object associates names with values. They organise data differently. Try these lines in the Console and read the two console.log results:

const milestones = [3, 5, 10];
const settings = { name: "Ada", limit: 10 };
console.log(milestones[0]); // 3: the first item has index 0
console.log(settings.name); // Ada: a property by name

This example is separate from the counter: you do not need to copy it into script.js to finish the exercise.

Values have different types

The clicks count is a number; a name read from a field is a string. Conditions produce true or false, boolean values. Open the browser Console and run this block: each line prints a type and a value.

console.log(typeof 3, 3);           // number 3
console.log(typeof "3", "3");       // string "3"
console.log(typeof true, true);     // boolean true
console.log(typeof undefined);      // undefined
console.log(null);                  // null: an explicitly empty value

undefined often means a value has not been assigned; null is an absence set explicitly. querySelector also returns null when it finds no element. Historically, typeof null returns "object": use === null to check for it.

An HTML input returns text even when you type a number. Predict the results before running these lines:

console.log(3 + "1");             // "31"
console.log(3 + Number("1"));     // 4
console.log(Number("three"));     // NaN
console.log(Number.isNaN(Number("three"))); // true

+ joins text if either value is a string. Number() converts numeric text; text that is not numeric produces NaN. An empty string also becomes 0: check that an input is not empty before converting it. Change "1" to "5" and check that the result is 8.

Combine conditions

The counter uses === to compare an exact value. If a goal comes from an input, convert and check it first. This example uses a goal written as text, just like input.value. Paste it into the Console: it should print “Goal reached”.

{
  const goalText = "3";
  const goal = Number(goalText);
  const clicks = 3;
  const valid = goalText.trim() !== "" && Number.isInteger(goal) && goal > 0;

  if (valid && clicks >= goal) {
    console.log("Goal reached");
  } else {
    console.log("Keep going or correct the goal");
  }
}

!== means “different” without conversion; && requires both conditions to be true; >= means “greater than or equal to”. Number.isInteger() excludes decimals and NaN. Change "3" to "0", then "three", then change clicks to 2: each time the other message should appear.

Use || (“or”) when either condition is enough; ! reverses a boolean. For example !valid is true when the goal is invalid. A condition should express the rule you want to apply.

Know where a variable exists

In messageFor(clickCount), clickCount is a parameter: it receives the value passed to the call. The function gives text back with return. The name created inside the listener exists only in that block; clicks, declared outside, stays available to the listener and keeps the count between clicks.

Run this block in the Console. You should see “Clicks: 2” and “Clicks: 5”; the original value remains 2.

{
  const clicks = 2;
  function messageFor(clickCount) {
    const text = `Clicks: ${clickCount}`;
    return text;
  }
  console.log(messageFor(clicks));  // Clicks: 2
  console.log(messageFor(5));       // Clicks: 5
  console.log(clicks);              // 2
}

text and clickCount exist inside the function; you cannot read them outside it. Variables declared with let and const stay inside their { ... } block. This separation stops one part of a program from accidentally changing another part's temporary data.

Use arrays, objects and loops

An array keeps values in order. An object groups named properties. A loop checks several values without writing a separate line for each one. Try this in the Console: with five clicks, goals 3 and 5 should appear, but not 10.

{
  const goals = [3, 5, 10];
  const state = { name: "Ada", clicks: 5 };

  for (const goal of goals) {
    if (state.clicks >= goal) {
      console.log(`${state.name}: reached ${goal} clicks`);
    }
  }
  console.log(goals[0]);      // 3
  console.log(goals.length);  // 3
}

goals[0] is the first item: indexes start at zero. state.clicks reads the object's clicks property. for...of takes one array item at a time; if decides whether to show it. Change clicks: 5 to clicks: 10 and check that all three goals appear.

You can add a goal with goals.push(15) and change the count with state.clicks = 6. const prevents reassigning goals or state to another value, but it does not freeze the contents of an array or the properties of an object. This experiment is separate from the counter file: do not copy it into script.js.

Change an array and an object

The earlier experiment read data. Now change it: paste this block into the Console. The first milestone stays 3, but the array has four items and the object’s limit becomes 15.

{
  const milestones = [3, 5, 10];
  const settings = { name: "Ada", limit: 10 };
  milestones.push(15);
  settings.limit = 15;
  console.log(milestones[0]);       // 3
  console.log(milestones.length);   // 4
  console.log(milestones.includes(15)); // true
  console.log(settings.limit);      // 15
}

push adds a value to the end of an array; length counts items; includes looks for a value. The limit property changes with =. const prevents assigning a different array or object to the same variable, but does not prevent changes to its contents. Change 15 to 8 in the push call: includes(15) becomes false.

Use an array for an ordered sequence and an object for named data. You can also put objects inside an array: you will do that on the page in the next step.

Put arrays, objects and a loop on the page

Add something to the counter you have already finished. In index.html, after the result paragraph, add a button and an empty list:

<button id="show-milestones" type="button">Show milestones</button>
<ul id="milestone-list" aria-label="Milestones reached"></ul>

At the end of script.js, after the Reset code, add this block. It uses the same clicks variable as the project; it does not replace the earlier code.

const milestones = [
  { threshold: 3, label: "First milestone" },
  { threshold: 5, label: "Second milestone" },
  { threshold: 10, label: "Third milestone" }
];
const showMilestonesButton = document.querySelector("#show-milestones");
const milestoneList = document.querySelector("#milestone-list");

showMilestonesButton.addEventListener("click", () => {
  milestoneList.replaceChildren();
  for (const milestone of milestones) {
    if (clicks >= milestone.threshold) {
      const item = document.createElement("li");
      item.textContent = milestone.label;
      milestoneList.append(item);
    }
  }
});

Save, reload and click the counter five times. Press “Show milestones”: two items appear. Press Reset and then “Show milestones” again: the list becomes empty. for...of examines each object; if keeps only reached thresholds; createElement and append build the list. replaceChildren() rebuilds it from the current count, so you do not need to change the Reset code.

Recognise and handle an error

You have seen that querySelector returns null for a missing ID. Reading textContent from null causes an error. Check the value first; try this in the Console:

{
  const element = document.querySelector("#missing");
  if (element === null) {
    console.log("Element not found");
  }
}

Other operations can fail while running. try/catch lets you react to an error. This experiment creates one deliberately; you will see “Example error” in the Console:

try {
  throw new Error("Example error");
} catch (error) {
  console.log(error.message);
}

An if check is clearer for predictable problems such as a missing element. Use try/catch when an operation can still fail, such as a network request. When an error appears, read its message, file and line in the Console before changing code.

Wait for a result while the page stays responsive

The listener waits for a click without blocking the browser. A timer or network request also produces a result later. This experiment runs in your page's Console without a server: you should see “Start” immediately and “Finished waiting” about a second later. The counter button still works in the meantime.

{
  const wait = (milliseconds) => new Promise((resolve) => {
    setTimeout(resolve, milliseconds);
  });

  async function tryWaiting() {
    console.log("Start");
    await wait(1000);
    console.log("Finished waiting");
  }

  tryWaiting();
}

setTimeout schedules an action for later. The Promise represents a result that will arrive. async lets you use await: the function pauses until the Promise resolves, while the page remains responsive. Change 1000 to 2000 and observe the difference.

fetch() uses the same mechanism for network requests and returns a Promise. A server response can fail: in a real app you would check response.ok and handle errors with try/catch. Here you first learn to wait with an example you can actually run.

Keep a value after reloading

The clicks variable resets whenever you reload. localStorage can keep a string in the browser. Convert it when reading it back as a number:

localStorage.setItem("clicks", String(clicks));
const savedValue = localStorage.getItem("clicks");
const savedClicks = savedValue === null ? 0 : Number(savedValue);

These lines show the operations; they are not a complete new script.js. The data stays in the browser until you delete it. Do not store passwords or sensitive information there.

Wait for a response from a server

A click is an event that arrives later. A network request also finishes later: async and await let a function wait for a result without blocking the whole page. This example needs a server responding at /api/message; it will not work by opening the HTML file alone.

async function loadMessage() {
  try {
    const response = await fetch("/api/message");
    if (!response.ok) throw new Error("Invalid response");
    const data = await response.json();
    result.textContent = data.message;
  } catch (error) {
    result.textContent = "Could not load the message.";
    console.error(error);
  }
}

try/catch handles errors, such as a lost connection. The example shows where the function waits and where it displays the result; it does not replace the counter project.

Choose when a script starts

In the project we used defer: the browser downloads the file while parsing HTML and runs it once parsing is complete. A classic script without attributes in the head can pause HTML parsing. async runs the script as soon as it is ready, so it does not guarantee that page elements exist yet or preserve order relative to other scripts. type="module" scripts are deferred by default.

While a function waits for a network request, the browser can handle other work, then resume the function when the result arrives. This coordination involves the event loop. For the first experiment, it is enough to know that the listener code starts on a click, not when the page loads.
